# Digital Fly Car

В репозитории сохранены фаворит, исходная версия до компаса, промежуточная broad-round1 и отчёты галереи. Большие учебные данные и исходный архив коннектома остаются локальными. Для просмотра уже сохранённой модели исходный архив не требуется; нужно установленное Python-окружение с зависимостями.

**Навигация по папке:** [что запускать и за что отвечают файлы](../PROJECT_MAP.md) · [служебные сценарии](../scripts/README.md) · [отчёты и планы](README.md).

13/16 простых и 7/7 старых. Она установлена в `artifacts/imitation/connectome.pt`
и `connectome.best.pt`; неизменяемая копия — `versions/main-23of32.pt` в той же
папке. Прежние веса сохранены в `backups/before-main-23of32-20261009`.
Это выбранная пользователем рабочая версия; прежний строгий критерий
независимой приёмки она не прошла.

Выбери карту и нажми «Запустить карту»; доступны остановка, повтор и скорость просмотра 0,5–4×. Терминал пульта должен оставаться открытым. Просмотр запускает сохранённого фаворита без учителя и без обучения. [Устройство и проверка галереи](2026-10-10-live-map-gallery.md).

## Новый эксперимент: коннектом + imitation / DAgger

В `Digital Fly Car.command` доступны «Учиться у учителя», «Проверка без
учителя» и «Новая муха в MuJoCo». Прежние режимы находятся в раскрывающемся
разделе, их память сохранена. Если пульт уже запущен со старым кодом, один
раз закрой его терминал и снова открой `.command`, затем обнови страницу.

Для нового эксперимента машинка должна остановиться в пределах **0,5 м от
центра шара**: скорость не выше 0,03 м/с в течение 0,5 с. Въезд в шар не
требуется. Учитель учитывает bicycle-кинематику и внешние края колёс.
Первые шесть эпизодов он ведёт машинку сам; до 24-го помощь уменьшается.
Затем повторяется цикл: два проезда учителя, два смешанных с вероятностью
помощи 50%, два самостоятельных. Цикл продолжается по сохранённому общему
счётчику, не сбрасывается при новом запуске. Во всех обучающих проездах
ученик получает правильные команды учителя для своих наблюдений. Проверка
работает без учителя. График показывает ошибку имитации, а не RL-награду.

В новой сети 255 нейронов и 4 088 связей из FlyWire v783. Это небольшой
анатомический подграф с обучаемыми адаптерами камеры/датчиков и моторов,
не полный мозг мухи. Во втором варианте селектора доступна обычная RNN.
Модели сохраняют веса, оптимизатор и последние 128 размеченных эпизодов
в `artifacts/imitation/connectome.pt` или `rnn.pt`; следующий запуск
продолжает обучение. Старые Q-таблицы в `artifacts/rl` не меняются.

Обучение постепенно добавляет повороты, слалом, закрытую цель и старты возле
препятствия, в том числе с целью вне кадра. Каждый шестипроездный цикл
посвящён одному типу карты: учитель показывает полный маршрут, затем ученик
пробует его с помощью и самостоятельно. Схемы зеркалятся и немного смещаются.
Старты с пересечением препятствия запрещены. Это ещё не гарантия восстановления
после любого реального контакта: некоторые тесные положения сам учитель
пока не умеет проходить.

При первом запуске нового отбора и далее каждые 12 накопленных эпизодов
идёт самостоятельная проверка на семи фиксированных картах. В пульте она
отображается отдельно от успехов с помощью учителя. Это проверочный набор
для выбора модели, не независимый итоговый научный тест.
Последняя память остаётся в `connectome.pt` / `rnn.pt` для продолжения обучения;
лучшая по числу успехов, затем контактам и расстоянию — отдельно в
`connectome.best.pt` / `rnn.best.pt`, отчёт — в `.validation.json`.
Проверка и MuJoCo через пульт используют лучшую, если она есть, иначе последнюю.
Для этих изменений пульта один раз перезапусти `.command` и обнови страницу.

Начни с 12 эпизодов, затем выбери «Проверка без учителя». Успехи смешанных
проездов во время обучения не доказывают навык ученика. Короткие пробные
обучения пока не дали надёжной навигации, их веса не подставлены в основной
режим. Установка, происхождение данных и результаты: [отчёт](2026-10-06-connectome-imitation.md).

## Прежние модели

Симуляция RC-машинки с bicycle-кинематикой и рекуррентным нейронным контроллером, вдохновлённым зрительными реакциями мухи. Контроллер получает камеру, yaw-rate, encoder, ToF и контакт; координаты цели используются только для оценки результатов. Нейронные популяции обновляются с шагом 0.02 с (50 Гц симуляционного времени). Это rate-модель, а не спайковая модель и не обучение весов во время езды.

Красный шар распознаёт HSV mock backend `MockRedBallDetector` за интерфейсом `ObjectObservation`. YOLO и распознавание произвольных предметов пока не подключены. Знакомые виды камеры могут сохраняться между интерактивными запусками; моторные веса, компас и кратковременное нейронное состояние не сохраняются.

## Запуск двойным кликом

В Finder дважды нажми `Digital Fly Car.command` в текущей папке проекта.
Откроется постоянный веб-пульт на http://127.0.0.1:8765. Выбирай режим,
параметры и нажимай «Запустить эксперимент». После завершения или «Стоп»
можно сразу запустить следующий режим; закрывать терминал не нужно.
Терминал с пультом оставь открытым. Повторный двойной клик открывает уже
работающий пульт. Старую запущенную симуляцию на порту 8765 перед первым
запуском нового пульта нужно закрыть.

«Обучение объезду» — отдельный эксперимент с одним цилиндром, разными
стартами и положениями цели. Газ/руль выбирает RL, готового манёвра обхода
нет; остаются ограничения направления по бамперам. «Проверка объезда»
использует отдельные карты и не меняет таблицу. «Объезд в MuJoCo» показывает
эту модель на выбранной карте. Успех здесь — въехать в шар: центр корпуса
должен оказаться в пределах 5 см от центра шара (вид сверху);
остановка при завершении viewer выполняется симулятором, не выучена мухой.

Память объезда: `artifacts/rl/bypass-policy.json`. Первый запуск начинает
новую таблицу, следующие продолжают её. Общая память `q-policy.json` не
переписывается. Сохранение атомарное после эпизода и при кнопке «Стоп»;
незавершённый шаг тоже сохраняется. Награды: продвижение к цели +8/м,
достижение +40, время −0,15/с, контакт −2 при начале и −0,8/с удержания,
небольшой штраф смены руля. Координаты используются только оценщиком,
не передаются управлению. Сначала пробуй 120 эпизодов, затем проверку 20;
это эксперимент, успешный объезд заранее не гарантируется.

В симуляции теперь шесть идеальных дальномеров: передний, два диагональных
под 45°, два боковых и задний. Боковые и диагональные стоят у внешней
границы колёс; это лучи MuJoCo, не модель ультразвука. Их показания и схему
направлений видно в телеметрии, лучи — в MuJoCo. Новые показания учитывает
RL объезда; обычная навигационная таблица пока использует прежнее состояние.
Старая память объезда не сбрасывается: девять прежних признаков дают начальные
оценки для новых состояний с боковой/задней близостью, затем они обучаются
независимо. Перед продолжением сохраняется резервная копия таблицы.
Уже работающий эксперимент использует прежний код: останови его кнопкой
«Стоп» и запусти следующий из того же пульта.

Штраф не запрещает действие мгновенно: Q-learning обновляет оценку только
после опыта в конкретном состоянии. Неиспробованное действие с оценкой 0
может выиграть у оштрафованного с отрицательной оценкой; при обучении также
остаются случайные действия (epsilon). Поэтому наличие штрафов само по себе
не гарантирует объезд. Начальная четверть карт обучения легче остальных,
так что сравнение первой и последней четверти не является чистой оценкой
прогресса — для этого используй отдельную «Проверку объезда».

Камера и телеметрия встроены в пульт, журнал и график наград остаются после
окончания запуска. Одновременно допускается только одно задание. Кнопка
«Стоп» главного пульта останавливает процесс; кнопки миссии внутри камеры
не управляют обучением. Python берётся из
`/opt/miniconda3/envs/flybrain/bin/python`; окружение должно существовать.

Dashboard показывает камеру, сенсоры, нейронные активности и команды моторов. Управление позволяет начать, остановить и сбросить миссию. Остановка обнуляет команды моторам. Подключение к работающему серверу: `python run.py dashboard --attach 127.0.0.1:8765`.

## Команды

Из папки проекта:

```bash
conda activate flybrain
python run.py sim --scenario corridor --dashboard
python run.py sim --scenario random --seed 12
python run.py sim --scenario slalom --genome path/to/genome.json
python run.py test
```

На macOS `run.py` переключается на `mjpython` для viewer. Карты: `corridor` — прямой коридор; `turn_corridor` — поворот; `slalom` — чередующиеся препятствия; `blocked_goal` — закрытая цель; `random` — процедурная арена. Единственный поддерживаемый `--target` — `red_ball`.

## Знакомство с окружением

Обычный запуск `python run.py sim` использует временную память без чтения и записи файлов. Для сохранения укажи `--memory PATH`. Запуск двойным кликом уже передаёт `--memory .local/familiarity.json`: он помнит виды между запусками. Файл атомарно сохраняется при нормальном закрытии или Ctrl-C, ограничен по размеру и числу записей и имеет проверяемую версию формата. Новая миссия получает свежие компас, motion и нейронное состояние, сохраняя знакомство с видами текущего сеанса.

```bash
python run.py sim --dashboard --memory path/to/familiarity.json
python run.py sim --dashboard --memory .local/familiarity.json --reset-memory
```

`--reset-memory` требует явный `--memory PATH`, переносит старый файл в соседний `*.backup-*`, затем начинает пустое хранилище; резервную копию можно восстановить переименованием. Повреждённый файл вызывает диагностическую ошибку и остаётся нетронутым. Оценка использует отдельную пустую память для каждой карты и не читает интерактивное хранилище.

## Оценка и эволюция

```bash
python run.py evaluate --suite type-a
python run.py evaluate --suite type-b
python run.py evaluate --suite train --episodes 20 --start-seed 0
python run.py evaluate --suite scenarios
python run.py evaluate --scenario corridor --genome path/to/genome.json
python run.py evolve --config path/to/evolution-config.json --out path/to/results
```

Эволюция использует тренировочные карты. JSON конфигурация соответствует `EvolutionConfig`; сохраняются checkpoint и `best-genome.json`. Для воспроизводимости фиксируй конфигурацию, seed и геном. `type-a` и `type-b` — фиксированные наборы по 10 карт; `--episodes` выбирает первые N. `train` и `random` генерируют N карт, `scenarios` запускает каждую именованную карту один раз.

Оценка выводит JSON каждой попытки и итог. Нулевой код требует успешность не ниже 90% для Type-A, 70% для Type-B, 75% для остальных наборов и отсутствие столкновений и проникновений. `--required-rate` меняет порог успешности. Порог приёмки не является заявлением о достигнутом результате; измеренные результаты кандидата документируются отдельно после проверки.
